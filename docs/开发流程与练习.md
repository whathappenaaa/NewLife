# 跟着 New Life 学习开发

这份说明对应已经存在的代码。每次练习先运行现有版本，观察一个行为，再改一个小点并验证。

## 第一课：运行工程和观察点击

独立环境 `.venv` 保存这个项目需要的 Python 包。VS Code 的解释器必须指向 `.venv/Scripts/python.exe`，这样运行、测试和调试会使用同一套依赖。

双击项目中的 `New Life.code-workspace` 可以打开带有项目名和解释器配置的工作区。

按 F5 运行“示例音频”配置。打开 `controller.py`，在 `trigger()` 的第一条语句左侧点出红色断点，再点击一条声音的头像。程序会暂停：观察 `path`，它是被点击文件的路径。用 F10 单步执行，观察程序如何判断“播放新片段”或“停止当前片段”；F5 继续运行。

练习：用头像点击触发断点，再点击波形。波形不应该进入 `trigger()`，因为它只连接范围编辑事件。

## 第二课：从界面走到音频线程

`ui.py` 中按钮调用共享控制器；控制器将命令交给 `audio.py`。窗口不直接操作声卡，也不在点击事件中读取整段声音。

音频引擎后台执行设备管理和混音，设备回调只读写有限缓冲。音频文件解码和片段导出使用工作线程。后台结果通过 Qt 信号回到界面，界面定时读取状态。

练习：给 `_play()` 和 `_on_audio_event()` 设置断点，播放短音效，观察开始和自然结束。然后点击停止：停止不会产生用于循环的“自然结束”事件。

## 第三课：理解片段范围与测试

`models.py` 的 `valid_range()` 限制范围至少 1 秒。`WaveformWidget` 拖动只发出起止时间；`controller.set_range()` 保存并更新播放中的范围。原文件完整保留。

运行测试：

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_controller.py -q
```

练习：播放一个音频，拖动终点；当播放位置超出新范围时，声音应从新起点继续。阅读测试中对应场景，理解“先准备状态，再执行操作，最后检查结果”。

## 第四课：保存、失败与恢复

`library.py` 按文件夹保存排序、范围、图片和快捷键。SQLite 事务保证一组设置一起保存。复制和导出先写临时文件，完成后才发布为正式音频；同名自动加序号。

录音先写隐藏 `.part` 文件，写入 WAV 头和数据。停止时完成保存；异常退出后扫描本软件的临时录音，尽量修复数据长度。失败需要告诉用户，不能只写一个空的异常处理。

练习：设置某个音频的范围和背景色，退出并重开，确认保持。观察日志目录 `%LOCALAPPDATA%/NiuLaiPlayerPython/logs`，定位发生错误的模块和时间。

## 第五课：从源码到用户能运行的软件

`build.ps1` 先运行测试，再用 PyInstaller 将 Python、Qt 和音频库装进 Windows 文件夹包。用户运行 EXE 时不需要安装 Python。EXE 与 `_internal` 要一起分发；虚拟音频驱动仍独立安装。

练习：运行发布包，选择一个不同的测试文件夹，导入提示音并播放。源码测试通过后仍要验证发布包，避免漏掉动态库、图片或编解码器。

后续修改的常用流程是：明确行为 → 找到所属模块 → 小范围修改 → 运行相关测试 → 实际操作验证 → 更新说明 → 发布。不要为了一个界面改动同时改动所有模块。

## 第六课：临时系统设置为何需要恢复记录（v0.2历史设计）

当前版本按最新需求采用永久保存，退出不恢复；以下用于学习旧版恢复服务，现行流程见第十一课。

这次新增的 `windows_audio.py` 只负责读取设备和修改默认通信输入；`system_settings.py` 负责保证生命周期正确。设备名称和编号会变化，所以恢复用 Windows 提供的完整端点 ID。

流程是：先把原设备写入恢复记录 → 临时切换 → 读回验证 → 断开或退出时检查当前值 → 恢复原设备 → 确认后清除记录。记录必须早于修改；否则在修改之后突然断电，程序将无法知道原设置。

退出不等同于隐藏。隐藏只是把窗口收起，进程和通话仍存在；退出必须保存录音，即使保存失败也要尝试恢复系统设置。若用户中途主动选择了其他设备，恢复程序不能覆盖这个新选择。

练习：阅读 `tests/test_system_settings.py` 的模拟设备。把原设备不可用设为真，观察恢复记录仍保留；再设为可用，确认恢复成功。测试使用模拟后端，不会改变真实 Windows 设备。强制结束和断电不能执行退出代码，没有守护程序时依靠下次启动恢复。

## 第七课：一个状态、多个界面

主窗口和迷你条共同读取控制器。迷你条固定头像标题宽度，过长文本采用省略号和提示。语言切换更新现有控件，避免重建窗口导致播放或尚未保存的设置丢失。

头像保存的是原图、原图中的裁剪矩形和256像素预览。界面显示预览，重新裁剪时打开原图。数据库只更新头像字段，不覆盖裁剪期间可能调整的新播放范围。

练习：播放示例音频时切换语言并修改头像。观察播放未重启，再检查 `tests/test_controller.py` 的语言切换测试。图标从 `assets/app.svg` 统一生成，EXE与Qt窗口使用相同资源。

## 第八课：从一个真实失败文件定位问题

这次无法识别的“WAV”实际是 MP4 容器里的 AAC 音频。扩展名是文件标签，改名字不会把内容转换成另一种编码。定位时先读文件头和媒体信息，确认事实，再决定修复所属模块；不要先给用户要求改文件名。

`media_decode.py` 统一检测、解码、波形和导出，避免四条流程各支持一套格式。给 `MediaDecoder.probe()` 设置断点，导入一个音频，查看识别到的编码、时长和音轨。测试使用生成的 AAC 文件改名成 .wav，确保今后这种情况仍能播放。

## 第九课：分清播放范围和播放位置

范围把手修改 start/end，进度轨道调用 `Controller.seek()`。两种事件命中不同区域，播放定位不改变范围。每次定位更新播放编号，旧线程发来的完成事件会被忽略，因此不会在跳转后错误切到下一首；麦克风缓冲独立保留。

练习：在 `seek()` 设置断点，播放示例后拖进度；观察 position 改变而 start/end 不变。再打开 `tests/test_controller.py`，查看定位后旧完成事件被忽略的测试。

## 第十课：让设置跟着文件走

SQLite 保存本机索引和排序，`.newlife` 包保存媒体配置及图片。包不记录旧电脑的绝对图片路径。保存时先写同目录临时包，校验并同步磁盘后再原子替换；失败时原包仍可读取，界面不能提前显示“保存成功”。

练习：调整示例音频的范围及图片，复制音频和 .newlife 到新文件夹，使用另一个测试配置目录启动，确认恢复。运行 `tests/test_integration_v03.py` 可以观察这条完整流程，测试不打开真实麦克风。


## 第十一课：让设备和界面对新用户更友好

本轮先确认行为：用户在软件或Windows更换设备都可以，修改长期保留。`windows_audio.py`读取稳定端点并更改默认设备；`controller.py`定期读取系统选择，只匹配唯一真实设备；`audio.py`在后台切换采集流，避免界面等待。名字重复、虚拟线或暂时不能识别时显示具体提示，不猜测设备。

`PersistentSystemSettings`不执行退出恢复，旧恢复记录归档以兼容历史数据。旧的临时服务保留用于历史行为测试，不作为新版本默认服务。改变需求时需要同步修改代码、测试和操作说明。

配色由style.py集中控制，主窗、迷你条、设置、裁剪和自绘控件共用颜色映射。拖动进度与范围把手分开命中区域；复选框整块36×36区域均可点击。测试不只点图标中心，还会点击边缘，验证扩大的区域真的有效。

练习：使用示例音频调试配置切换深色／浅色，观察播放状态不变。给Controller.follow_system_devices设置断点，在Windows声音设置更换现有耳机，观察端点匹配和后台切换。Windows设备修改会保留，练习后在系统中手动选回你希望使用的设备。

## 第十二课：把需求变成可验证的行为

表达需求不必先学术语。按“位置 → 当前问题 → 希望的操作和结果 → 保留什么 → 怎样验收”描述即可。比如“迷你条拖不动；希望从头像或标题拖动；单击仍播放，拖动不误播”。开发时再拆成窗口移动、点击判定和回归检查。

迷你按钮原先消费了鼠标事件，父窗口只能从极小的空隙拖动。MiniWindow现在观察头像按钮事件：按下先记录位置，超过系统拖动阈值才移动，并取消这次按钮点击；释放或隐藏清除拖动状态。给MiniWindow.eventFilter设置断点，比较普通点击和拖动。tests/test_mini_v05.py验证移动后没有触发播放，也检查正常点击只触发一次。

顶部控件读取Controller同一份状态。设备选择调用change_system_device；主题和置顶只调用set_theme、set_mini_on_top，保存失败时回显实际值，不重新启动音频链路。程序同步下拉框时屏蔽信号，避免一次Windows变化反过来触发新的系统修改。tests/test_controller.py中有保存失败和音频保持运行的检查。

程序根目录不等于当前工作目录。开发时根目录是项目位置；打包后是NewLife.exe的位置，MUSIC放在它旁边。_internal只装依赖和只读资源，不适合作为录音目录。music_folder.py统一解析路径；build.ps1复制MUSIC里的音频和配套.newlife。验证时从其他目录启动，再把整包复制到新位置，确认仍能找到自己的MUSIC。

练习：在VS Code按F5，选择“New Life：MUSIC 自带音频（独立配置）”录一个短片段，调整范围；退出后检查音频及.newlife，再打包。解压新包到另一个文件夹，用独立测试配置目录启动，观察范围自动恢复。只把准备分发的音频放进根目录MUSIC，原播放文件夹可以继续使用。

## 第十三课：把设计图变成真正的窗口（v0.6）

设计图确认后，先把行为分成三部分：窗口布局、波形操作、文件处理。`ui.py`负责把按钮放在固定比例的列里，`widgets.py`负责绘制和鼠标命中，`controller.py`负责让动作生效。这样缩短播放按钮不会意外改变音频线程或录音逻辑。

通话帮助和快捷键是独立的非模态面板，主窗口上的入口仍能点击。同一个按钮负责打开和关闭；切换页面时保留编辑草稿，而“保存快捷键”才提交设置。窗口关闭事件还负责恢复全局快捷键，避免看起来面板消失了、后台按键却一直失效。

波形有两种数据：start/end代表允许播放的范围，position代表当前播放位置。横轴和圆点只展示position，左右把手只编辑start/end。圆点本身的半径也要包含在范围内；点击另一行的进度不能把当前声音跳转到错误时间。测试要分别验证绘制边界、鼠标边缘命中和控制器状态。

删除先把音频和便携配置一起暂存，并写入恢复记录，30秒内允许撤销，再交给系统回收站。撤销前检查同名冲突，不能覆盖用户后来放进去的文件。文件移动、数据库更新或回收失败时要保留能够恢复的内容。界面显示的成功数量应来自真实结果，而不是用户选了多少个文件。

你可以这样验证本课：在VS Code按F5运行示例音频，连续两次点击“通话帮助”，观察打开和关闭；打开快捷键输入草稿，关闭再打开，确认还在。播放一条音频，拖中央圆点，再拖左右范围，比较position与start/end的变化。最后在独立示例文件夹删除两条音频并撤销，确认音频、头像、背景和范围一同回来。

发布时先运行相关测试，再跑完整测试，最后检查冻结EXE的不同语言、主题和缩放。源码能运行不能代替用户拿到的包也能运行；每次发布都要从其他目录启动，再把整包复制到新目录验证MUSIC和便携配置。
